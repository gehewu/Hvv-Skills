# 护网资产测绘方法论（红队 / 蓝队共用）

> 红队用它找入口，蓝队用它做自查。
> 核心：**种子不是资产；每个响应都在说话；先降噪再深挖；关联即情报。**
> 详细手法见同目录 `expansion.md`、`decisions.md`、`correlation.md`、`recon-tools.md`。

---

## 0. 与护网的结合

| 角色 | 用法 |
|------|------|
| 红队 | 从靶标清单出发，展开外网暴露面，找最容易进的入口 |
| 蓝队 | 从自有资产出发，找影子资产/废弃系统/边缘端口，收敛暴露面 |
| 自查 | 同蓝队，但只检测不利用 |

**边界：** 红队只展开清单内资产及其授权延伸；清单外不碰。蓝队自查范围按授权。

## 1. 工作流

### Phase 0 — 目标确认
- 输入：靶标清单 / 自有资产表 / 组织名 / 域名 / IP 段
- 明确：范围、时间窗口、交付物、ROE
- 建任务根：`D:\MCP\hvv\{行动名}\资产\{靶标}\`
- 落盘 `资产清单.md` 骨架

### Phase 1 — 种子收集
- 三件套：子域名、端口、目录（快速过）
- 扩展源（更值钱）：
  - 证书 CT 日志（crt.sh）：SAN 常列内部域名
  - 被动 DNS 历史：曾解析过的 IP
  - favicon hash：同源系统聚类
  - 供应链指纹：自研框架/网关/组件反查
  - 代码仓库、APK/小程序、Wayback、JS 残留
- 工具语法：`recon-tools.md`、`tools/`

### Phase 2 — 降噪与分级
- 404 分类：谁返回的（Web 服务器/框架/网关/CDN-WAF/软 404）
- 存活分级：中间件在应用没起 / 应用起业务空 / 正常响应
- 指纹去重：favicon、标题、静态资源、响应头、报错页
- 决策表：`decisions.md`

### Phase 3 — 扫描模型判断（扫之前必做）
- 发 5～10 个随机路径，看响应是否字节级一致
- 一致 → 可扫；不一致 → 软 404，需内容指纹二次过滤；全 403 一致 → 先打拦截层/旁路
- 成本 10 秒，省几小时

### Phase 4 — 深度展开
优先级：
1. 前端反推后端（JS → API 表、鉴权、环境地址、SourceMap）
2. 二级业务目录（读 JS/Swagger/路由，不硬爆）
3. 影子/边缘资产（证书 SAN、CT、被动 DNS、冷门端口/管控台）
4. 废弃/测试/老系统（test/dev/staging/uat/pre/gray；v1/v2 并存）
5. 反代/网关穿透（Kong/APISIX/Spring Gateway/Nacos 管理面）
6. 二开中间件与供应链指纹
7. 子系统/微前端（qiankun/micro-app chunk、API 前缀聚类）
8. C 端到 B 端串联（role/userType/isAdmin、admin/manage/console 关键词）
9. 开发运维视角（Prometheus/Grafana、Jenkins/GitLab、Jira/Confluence/YApi）

详见 `expansion.md`。

### Phase 5 — 关联编排
- 同代码/同网关/同模板 → 同漏洞
- 同 IP 段 → 内网互通
- 同证书/同 favicon/同解析 → 关联资产
- 供应链同指纹 → 一片
- 攻击路径推演：边缘 A 与核心 B 同 IP → 打 A 横到 B；测试 T 与生产 P 同源 → 先 T 后 P
- 详见 `correlation.md`

### Phase 6 — 输出
- `资产\资产清单.md`：去重、分级、证据
- `资产\攻击面地图.md`：关联关系、关键节点、薄弱环节
- `资产\推荐攻击路径.md`：按 ROI 排序
- `资产\未决项.md`：需账号/授权/更多时间
- 证据落 `证据\`，不靠对话记忆

## 2. 红队重点

- 先找“能进”的：VPN/OA/邮件/网关/中间件管控台/未授权 API/弱口令
- 再找“值钱”的：核心业务、数据库、域控、供应链
- 路径优先：边缘 → 跳板 → 核心
- 低特征：定向探测、低频率、避免大面积扫描
- 遇到疑似蜜罐：标记、绕开（见 `references/vulns/honeypot-recognition.md`）

## 3. 蓝队重点

- 影子资产：证书 SAN、CT、被动 DNS、历史解析、JS 残留、废弃系统
- 暴露面：公网管理后台、数据库、中间件、调试口、测试环境
- 第三方/云/外包：单独列，明确责任
- 收敛优先级：可直接进 > 可未授权读 > 需条件 > 信息级
- 输出整改清单与复测（见 `references/defense/self-assessment.md`）

---

## 4. 强制纪律

- 先降噪再深挖；先探针再扫描
- 识别 404/403 来源再决定打法
- 不只查 CVE：先打“默认开启但本该关闭”的功能面
- 被硬封锁就换入口，不硬撞
- 每个结论附证据（响应/指纹/hash/来源）
- 清单外资产不碰

---

## 5. 一句话

**种子不是资产，响应会说话；先降噪、再探针、后深挖、必关联。**
