# 降噪与扫描决策表（decisions）

本文是 Phase 2/Phase 3 的决策依据。原则：**从响应判断资产是否真在跑、跑的是什么、跑得活不活**，而不是看端口通不通、域名解不解析。

## 1. 404 分类表（判断"404 是谁返回的"）

扫到 404 默认扔掉是最大浪费。不同来源的 404 信息量天差地别，处置方式完全不同：

| 404 来源 | 特征 | 含义 | 下一步打法 |
|---|---|---|---|
| Web 服务器原生 | Nginx 默认页、Tomcat 默认页、Apache 默认页 | 裸的、没配好路由的中间件 | 打中间件：默认口令、管理端点、解析漏洞 |
| 应用框架 | Spring Whitelabel、Django debug 404、Next.js 404 页 | 应用活着、路径不存在，框架信息白送，常带堆栈/路径/环境变量 | 挖应用：确认框架版本 → 框架已知洞；读报错细节找信息泄露 |
| 网关 | Kong 的 message、APISIX `{"error_msg":"404 Route Not Found"}` | 这是网关，路由表里没这个 path | 打网关管理面、枚举其他路由、找后端 service 列表 |
| CDN/WAF | 云厂商定制 404 页 | 域名挂 CDN/WAF 后面，真实源站未找到 | 找真实源站（历史 DNS、证书、IP 段交叉） |
| 软 404 | 状态码 200，内容却是"页面不存在" | 最骗人，必须靠内容 hash/长度判断 | 用响应长度、内容指纹、hash 聚类判断，不能只看状态码 |

## 2. 存活分级（"存活"不是布尔值，是程度）

| 档位 | 现象 | 含义 | 攻击优先级 |
|---|---|---|---|
| 端口通、应用没起 | TCP 握手成功、HTTP 无响应或连接重置 | 中间件在、应用挂了/没部署 | **最值得打**：直接打中间件层（默认口令/未授权重灾区） |
| 应用起、业务空 | 首页能开、接口全 401/403/500 | 鉴权挡着或后端依赖挂了 | 高价值：绕鉴权、找未授权端点 |
| 正常响应业务 | 首页+接口正常 | 活系统 | 按正常流程继续展开 |

## 3. 403/404 该不该扫（扫描模型判断）

扫描本质是信息探测：发不同输入（路径），看输出（响应）有没有差异。**响应有差异 = 路径有区分度 = 扫描有效**；某一层把所有输入抹平成同一输出，扫一万个路径和扫零个获得的信息一样多。

### 3.1 先做探针（扫描前必做，成本 10 秒）

发 5~10 个明显不存在的随机路径（如 `/asdfqwertasdf12345`）：

- **全部字节级一致** → 拦截层在内容层之前，扫描结果可信 → 放心扫。
- **不一致** → 存在软 404 或动态处理 → 扫描结果必须用内容指纹二次过滤。
- **全部 403 且完全一致** → WAF/鉴权统一拦截 → 别扫路径，转旁路或先打拦截层本身。

### 3.2 403 判断（看是谁挡的）

| 来源 | 特征 | 结论 | 该做什么 |
|---|---|---|---|
| WAF/统一访问控制层 | 所有路径一律 403、响应字节级一致 | 路径扫描纯浪费 | 换 IP、降速率、分块绕 WAF；或放弃此入口走旁路（其他子域名/端口/客户端直连/历史 IP） |
| 应用鉴权 | 路径真实存在，响应有区分度（已认证但权限不足 / 未登录访问需登录资源） | 扫能发现路径但发现了一样 403 | 转找未授权可访问的同源接口、鉴权绕过（PUT/DELETE/PATCH 方法切换、大小写、末尾加点加斜杠）、找该资源的其他访问方式 |
| 反代/路由层 | 路由规则明确禁止 | 扫描无效 | 找网关管理面拿全量路由、改 Host/SNI 试虚拟主机 |

### 3.3 404 判断

| 情况 | 结论 |
|---|---|
| 全局统一 404（所有不存在路径返回字节级完全相同的 404 页） | **扫描的理想情况**，响应有任何差异就等于路径存在，放心扫 |
| 软 404 | 用响应长度、内容指纹、hash 聚类判断，不能只看状态码 |
| 网关 404 | 对这域名扫路径意义不大，但网关本身是目标：扫网关管理面和其他路由对应的域名 |

### 3.4 硬封锁判断

全端口都 403、所有 Host 头都 403、所有路径都 403、响应还完全一致 → 前面是一层硬 WAF/硬鉴权，入口彻底封死，继续耗是负收益。

正确做法：**标记为硬封锁**，把精力转到该资产的其他入口——一个后端不会只有一个入口，封死一个不代表全封死。

## 4. 去重聚类（几千条 → 几十个真实系统）

按 IP/域名去重没意义（几千条里大量是同一套应用的不同入口），必须按指纹：

- favicon hash（SaaS 和内部系统爱用默认 favicon，hash 一致就是同一套）
- 页面标题和 meta
- 特定静态资源路径
- HTTP 响应头组合
- 报错页特征

指纹一致的聚成一类，一类只深挖一个代表，其余标记同源。

## 5. 响应特征 → 行动 速查

| 你看到什么 | 意味着什么 | 做什么 |
|---|---|---|
| Nginx 默认 404 页 | 裸中间件 | 打默认口令/管理端点/解析漏洞 |
| Spring Whitelabel | 应用活着，框架白送 | 查框架 CVE + 读报错堆栈 |
| 全部路径 403 且字节一致 | 硬 WAF/鉴权 | 转旁路，标记硬封锁 |
| 响应有差异的 404 | 路径存在信号 | 放心扫 |
| 状态码 200 但内容"不存在" | 软 404 | 内容 hash 过滤 |
| 端口开、HTTP 重置 | 中间件在、应用没起 | 打中间件层 |
| 首页开、接口全 401 | 鉴权挡着 | 绕鉴权/找未授权端点 |
| 停放页 / 域名商默认欢迎页 | 非存活 | 丢掉不挖（§6.1） |
| 401 / 403 / 登录墙 | **存活**，有门 | 不丢，进站找业务面（§6.1） |

## 6. 站级处置：404 站 / 死站清洗（非存活、活筛、cold）

> 站级 404/不可达 ≠ 直接扔掉，也 ≠ 死透。先判「404 是谁返回的」（§1）→ 再清洗（本节）→ 再标记。
> 进站后的「某个接口返 404 别停」是另一类，见 §7。

### 6.1 非存活判定（清洗口径）

| 现象 | 判定 | 处置 |
|---|---|---|
| 探不通 / 超时 / 连接拒绝 | 非存活 | 丢掉不挖 |
| 停放页 / 域名商默认页 / 无业务响应 | 非存活 | 丢掉不挖 |
| 空白 / 乱码 / 纯静态无接口壳 | 废壳 | 丢掉或一眼证伪 |
| **401 / 403 / 登录墙 / 管理台挑战页** | **存活** | **不丢**；按 §1 判层后进站找业务面 |
| 框架 404（Whitelabel / debug 页） | 应用活着 | 不丢，按 §1 打法 |
| 网关 404（Kong / APISIX 报文） | 网关活着 | 不丢，打管理面、枚举路由 |
| 长期死页 / 失去更新的壳 | 冷 | 本轮不再碰 |

**401 / 403 / 登录墙 ≠ 死站**——那是「活着且有门」，常是后面有业务面的信号。当死站丢掉是最大浪费之一。

### 6.2 判死禁令（防误杀）

- **禁止只凭一条判死：**
  - 仅根域/www 连不上 → 必须再查 crt.sh / 被动 DNS / 历史解析 / 子域；**根域 404 或停放 ≠ 全站死**（业务常只挂 api / admin / portal 类子域）
  - 仅首页 404 → 换子域、端口、常见 path 再探一轮
  - 仅 401/403/登录墙 → 算活
- **一口证伪才可判死**：403 + 首页无业务 script + 中间件禁目录特征（Apache/TAPISIX 类）→ 证伪标 cold，不开线程
- 有业务味（登录、API、后台、Swagger、管理台、证书带业务名）→ 升活，无论首页是否 404

### 6.3 活筛 5 步（长尾域名 / 批量候选池，低成本筛选）

批量候选（备案长尾、搜索引擎导出、子域枚举结果）先便宜筛，活了再深挖，死的直接跳：

```
候选 d
  1) 根 DNS？无解析 → 不立刻判死，先做 3)
  2) 根/www 短超时探 80/443 → 有业务味升活；停放/连不上 → 进 3)
  3) crt/被动子域 → 有用子域升活；0 且根/www 死 → cold
  4) 可选：搜索引擎/FOFA 条数探针（无配额跳过）
  5) 通过 → 正式展开 → 去废去非存活 → 进站
```

- 无搜索配额时活筛只靠 DNS + HTTP + crt，**禁止为空筛再刷搜索**
- 搜索命中仍快弃：空/极少且全默认页；标题同质停放；只有无关端口 → 立刻换下一条，禁止硬抠
- 队列状态只认 `pending / doing / done / cold`；cold 写明原因（死备案/纯停放/无解析/证伪），本轮不再碰；新证据（新子域/新 path/新端口）出现可复活

### 6.4 软 404 的站级教训（实测）

> 出自教育网站点测绘与存活确认实测（`渗透测试报告/UEditor_edu站点测绘与存活确认报告.md`）：

- **200 不足以判存活**：大量站点对任意路径返回 200 + 软 404 页；存活确认必须带内容指纹/长度差分，不能只看状态码
- **命中串大小写差会造假命中**：FOFA 命中 `/UEditor/`（大写）几乎全是软 404，真实路径是小写 `/ueditor/`；页面引用判断会严重高估存活率
- 存活确认用低噪探针（每主机 ≤2 个 GET：根 + 关键 path），不带 payload、不登录、低并发；**先洗池再进站**

### 6.5 该去 / 不该去

| 该去（丢掉） | 不该去 |
|---|---|
| 重复条（同 host:port） | 同 host 不同 path / 接口 |
| 假 TLD、业务键当域名 | 同 host 不同端口（业务不同） |
| CDN / 静态 / 第三方库域 | 同品牌不同业务 host |
| 内网 IP、无关站 | **401/403/登录墙/管理台挑战页** |
| 空白/乱码/纯静态无接口壳、长期死页 | 框架 404 / 网关 404 背后的应用与管理面 |

### 6.6 与流程的衔接

- 靶标闭环里「去重 → 去废 → 去非存活」的口径以本节为准（`../hw-rules/workflow.md` §1）
- 站不可达 / 硬封锁无旁路 / 纯废壳 → 记 `blocked` 或 `cold` 换下一条，不提问停工

## 7. 接口级响应：404/403 别当终点（散落规则汇总）

> 站级判完进站后，还要防一类误判：**某个接口返 404 ≠ 这个功能没有**。
> 以下是知识库各处「404 别停」现场规则的汇总；细节仍在各出处原文。

| 你看到 | 别当终点 | 真正要打 | 细节出处 |
|---|---|---|---|
| 公开列表 / contents 404 | 不是没内容 | 同一 id 打 hidden/contents/tab/预览/导出；列表口加可见性参数 | `../vulns/auth-idor.md`「列表过滤详情不闸」 |
| 站内查单口 404 | 不是没单 | 打生产查单口（演示/预下单环境常见两套口） | `../vulns/auth-idor.md`「开放支付假签枚举 appId」 |
| 鉴权/permission 口 404 | 不是没入口 | 直接打公开下载/详情口；缺参改 GET query | `../vulns/file-upload.md`「分享鉴权 false 仍下媒体」 |
| 云凭证路径 404（`security-credentials/角色`） | 不是没钥 | 换 `service-role-security-credentials/角色` 再打 | `../vulns/ssrf.md`「云厂商路径差」 |
| config/密钥文件 404 | 不是没配置 | 同目录换名：`App.config`、`*.exe.config`、`bin/*.dll.config`、`*.pdb` | `../vulns/path-traversal-lfi.md`「静态桶 .NET 发布物」 |
| GET list 404 | 不是没接口 | 换 POST 才出数（列表类常见不对称） | `../vulns/auth-idor.md`「身份域账号 CRUD」 |
| path 报 auth failed / 缺版本 | 不是没口 | 按前端替换规则补 `/v2/` 等前缀再打 | `../vulns/auth-idor.md`「列表过滤详情不闸」 |
| 详情口报“已补/项目不存在” | 不是没数据 | 换 visit-log / 埋点 / doc-add-visit-log 同数字 id | `../vulns/auth-idor.md`「列表过滤详情不闸」 |
| 兄弟口 302/404 | 不是整站没口 | 同套其它前缀/功能口仍打（如 settle 口 302 别当整站没口） | `../vulns/auth-idor.md`「入驻 H5」 |

**通用原则：**

1. 404 = 「这条 path 不存在 / 没配路由」，不等于「这个功能没有」。常见变体：hidden/tab/预览/导出另有口、缺版本前缀、GET/POST 不对称、网关路由差、演示与生产两套口、列表过滤后空但详情有。
2. 先按 §1 判 404 是谁返回的：网关 404 → 找路由/管理面；应用 404 → 换 path/参数/前缀/METHOD；软 404 → 内容指纹确认。
3. 停不停看语义：**功能应该有却 404**（前端有按钮/JS 有调用/文档有记载）→ 换写法继续；**纯猜测枚举本来就没有** → 别磨，记 N/A 换面。
4. 接口 404/403 与 §6 站级清洗的分界：**站级**判「这个 host 挖不挖」；**接口级**判「这条口停不停」。别用站级判死把接口级机会一起扔掉。
