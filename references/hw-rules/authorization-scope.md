# 护网授权与范围（硬规则 · 第一优先级）

> 本文件为最高优先级。护网的第一事故不是“没打穿”，是“打越界”。

---

## 1. 唯一依据

按优先级：

1. **授权书 / 委托书**（书面，含范围、时间、动作边界）
2. **靶标清单 / 目标资产表**（IP、域名、URL、APP、账号）
3. **本届护网 ROE / 行动手册 / 指挥部通知**
4. 口头指令（仅在书面授权范围内做细化，不能扩大范围）

---

## 2. 开工核对清单（缺一项不开打）

- [ ] 授权主体、被授权人、行动名称、时间窗口
- [ ] 靶标清单：IP / 域名 / URL / APP / 账号，逐项确认
- [ ] 明确“算范围内”的关联资产判定口径（子公司？控股？云资源？第三方托管？）
- [ ] 明确禁止项（社工、钓鱼、供应链、DoS、拖库、后门……）
- [ ] 报备通道与联系人（指挥部 / 裁判组 / 带队人）
- [ ] 交付要求（日报、成果报告、证据格式）
- [ ] 已落盘 `00-授权与范围.md` 与 `01-ROE与报备.md`

---

## 3. 范围的三层边界

### 3.1 目标边界

- **只打清单内**。清单外目标：不扫描、不探测、不访问、不猜解。
- 清单内资产的“自然延伸”是否算范围内，按 ROE 口径：
  - 通常算：清单域名的子域、清单 IP 的开放端口、页面/JS 带出的同业务 API
  - 通常不算：控股/参股公司自有域、第三方 SaaS、CDN/云厂商基础设施、员工个人设备、供应链厂商
  - **拿不准 → 停手 + 上报**，不要“先打了再问”

### 3.2 时间边界

- 只在授权时间窗口内做攻击性动作；窗口外只做分析、报告、复盘
- 值守/夜间行动按指挥部排班；非本人时段不做未报备动作
- 紧急情况（如误触生产告警）立即停手并同步

### 3.3 动作边界

- 允许：探测、验证、利用、取权、留证（在 ROE 内）
- 需报备：提权、横向、留后门、触碰核心系统、大规模扫描、社工
- 禁止：见 `rules-of-engagement.md`

---

## 4. 越界判定与处置

**立即停手的信号：**

- 目标不在清单
- 解析到非清单 IP / 第三方云 / 外包系统
- 页面出现“非本靶标业务”的明显标志
- 动作可能影响生产（写操作、并发、重启类）
- 触发大面积告警或封禁

**处置流程：**

1. 停手，保留现场（请求/响应/截图/时间）
2. 判断是否已造成影响
3. **立即上报**带队人/指挥部，不隐瞒、不自行“补救”
4. 按指令决定：继续 / 绕开 / 放弃 / 协助处置
5. 记入 `日志\操作时间线.md` 与 `协同\`

> 越界后隐瞒不报 = 最严重违规。主动上报通常可从轻，隐瞒一定从重。

---

## 5. 范围变更

- 只能在书面授权更新后扩大范围
- 口头“可以打”需记录：时间、来源、内容，并在日报中注明
- 新增靶标 → 更新 `00-授权与范围.md` + 靶标队列，再开打

---

## 6. 靶标队列管理

`资产\靶标队列.md`：

| 靶标    | 类型 | 优先级 | 状态                       | 负责人 | 备注                 |
| ------- | ---- | ------ | -------------------------- | ------ | -------------------- |
| xx 系统 | Web  | P0     | pending/doing/done/blocked | —     | 入口、账号、特殊限制 |

- 状态只认：pending / doing / done / blocked / out-of-scope
- 一个靶标闭环（见 `workflow.md`）才标 done
- blocked 必须写原因（不可达/硬封锁/需授权/等账号）

---

## 7. 一句话

**清单内、窗口内、动作边界内；拿不准就停手上报。**
