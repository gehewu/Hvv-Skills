# 蜜罐识别（红队）与蜜罐运用（蓝队）

> 护网里红队最怕“打得太顺”——可能是蜜罐。蓝队则用蜜罐做发现与溯源。
> 原则：红队**识别、绕开、不投毒**；蓝队**部署、观察、取证**。

---

## 1. 红队：蜜罐常见特征

| 特征 | 说明 |
|------|------|
| 太容易 | 默认口令直接进、未授权直接出大量数据、漏洞一打就中 |
| 数据太假 | 姓名/手机号/订单明显是生成的；数据量异常大且整齐 |
| 环境不一致 | 版本/OS/中间件与业务不符；时间戳异常；无真实业务流量 |
| 响应异常 | 回包模板化、错误信息过于友好、延迟固定 |
| 网络异常 | 开放端口过多、无上下游依赖、DNS/证书奇怪 |
| 已知蜜罐指纹 | HFish、Conpot、Cowrie、Glastopf、Dionaea、T-Pot 等特征 |
| 诱导性强 | 文件名/路径明显诱惑（`passwords.xlsx`、`/admin_backup`） |
| 无副作用 | 命令执行“成功”但无真实系统痕迹；文件上传后无解析 |

---

## 2. 验证方法（低成本）

1. **数据真实性**：抽样看是否像真实业务（关联性、历史、格式）
2. **行为一致性**：执行无害命令看系统反馈（`whoami`、`hostname`、`ps`）是否合理
3. **网络侧**：外连是否被记录/阻断；DNS 是否异常；是否有反向探测
4. **时间**：文件时间、日志时间是否自洽
5. **业务上下文**：是否有真实用户/订单/上下游
6. **指纹**：HTTP 头、证书、favicon、默认页面、已知蜜罐特征

> 验证也用低特征、无害动作；不要上传真实工具、不要投毒、不要留后门。

---

## 3. 遇到疑似蜜罐怎么办

- **标记**：在资产清单标 `疑似蜜罐`，不投入深挖
- **不投毒**：不上传恶意样本、不填假数据污染、不反制
- **不消耗**：不在这里磨时间；换真实目标
- **报备**：同步带队人，避免队友重复踩
- **观察**：记录特征，供后续识别

---

## 4. 蓝队：蜜罐运用

- 部署：与真实资产同网段/同风格，覆盖常见入口（Web、SSH、RDP、数据库、VPN）
- 诱饵：假账号、假文件、假配置、假漏洞
- 监控：登录、命令、文件、外连、扫描
- 取证：记录源 IP、TTP、样本、时间线
- 溯源：关联其他告警，形成攻击者画像
- 注意：蜜罐本身要隔离，不能成为跳板；不收集无关个人信息

---

## 5. 检查清单

- [ ] 是否“太顺”？（默认口令/未授权/一打就中）
- [ ] 数据是否真实、自洽？
- [ ] 系统反馈是否合理？
- [ ] 是否有已知蜜罐指纹？
- [ ] 是否已标记、报备、停止深挖？
- [ ] 是否上传了真实工具/投毒？（禁止）

---

## 6. 一句话

**太顺先怀疑；验证用无害动作；标记、报备、不投毒、不消耗。**
