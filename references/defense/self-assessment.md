# 蓝队 / 自查：资产自查与暴露面收敛

> 目标：在红队之前，用攻击者视角把自己的暴露面摸清、收敛、整改。
> 与红队测绘共用方法，但**只检测、不利用**（除非另有授权）。

---

## 1. 工作流

```
资产盘点 → 暴露面发现 → 降噪分级 → 风险验证（只检测） → 整改 → 复测 → 台账
```

### 1.1 资产盘点
- 域名/子域、IP/网段、端口/服务、Web/API、APP/小程序、VPN/OA/邮件/边界设备
- 影子资产：证书 SAN、CT 日志、被动 DNS、历史解析、JS 残留测试域名、废弃系统
- 第三方/云资源/外包系统：单独列，标注责任方
- 输出：`资产\资产台账.md`（负责人、用途、重要性、暴露面）

### 1.2 暴露面发现
- 外部可直接访问的：管理后台、VPN、OA、邮件、数据库、中间件管控台、调试口、Swagger/Actuator
- 测试/预发/灰度/老版本：命名规律 test/dev/staging/uat/pre/gray；`/v1` `/v2` 并存
- 边缘端口：Nacos 8848、Apollo 8070、SkyWalking、XXL-Job、JMX、pprof、ES 9200、Redis、Docker 2375、YARN 等
- 参考：`references/recon/expansion.md`、`decisions.md`、`correlation.md`

### 1.3 降噪分级
- 404 分类 / 存活分级 / 指纹去重 / 扫描模型判断（同红队）
- 按“可被利用程度 × 业务重要性”排序：
  - P0：公网可直接进的后台/数据库/VPN/域控相关
  - P1：可未授权访问的业务 API/敏感文件
  - P2：需条件利用/内部暴露
  - P3：信息级/配置建议

### 1.4 风险验证（只检测）
- 未授权访问、弱口令（只试默认/少量，不爆破）、已知 CVE 验证、配置错误
- 不拖库、不写数据、不上传 webshell、不横向
- 验证到“能访问/能读到证明”即停，记录证据
- 高危立即上报，不在生产上继续深入

### 1.5 整改
| 优先级 | 动作 |
|--------|------|
| 立即 | 关停/下线、加认证、加白名单、改默认口令、打补丁 |
| 短期 | WAF 规则、访问控制、日志监控、最小暴露 |
| 长期 | 资产治理、上线流程、基线核查、供应链管理 |

- 无法立即修复 → 补偿措施（WAF/白名单/下线/监控/隔离）
- 整改责任到人、期限、验证方式

### 1.6 复测与台账
- 修复后复测：原路径 + 变体路径
- 复测用攻击者视角，不只跑扫描器
- 更新资产台账与风险台账，关闭项留证据

## 2. 自查重点清单

- [ ] 公网暴露的管理后台/VPN/OA/邮件/数据库/中间件
- [ ] 默认口令、弱口令、未授权访问
- [ ] 测试/预发/废弃系统仍在线
- [ ] Swagger/Actuator/heapdump/debug 暴露
- [ ] 云存储桶/OSS 公开读写
- [ ] 证书/域名/子域接管风险
- [ ] 第三方组件已知漏洞（有 PoC 的优先）
- [ ] 边界设备补丁与弱口令
- [ ] 日志/告警覆盖（能否发现红队动作）
- [ ] 备份/恢复与应急联系人

## 3. 交付物

- `报告\暴露面清单.md`（按 P0～P3）
- `报告\整改清单.md`（问题、责任、期限、验证）
