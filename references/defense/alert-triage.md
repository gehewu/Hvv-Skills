# 蓝队：告警研判

> 目标：从海量告警里快速判断“是不是真的、打到哪、要不要升级”。
> 原则：**证据优先、上下文优先、先处置后复盘。**

---

## 1. 常见告警类型与红队对应动作

| 告警 | 可能动作 | 重点看 |
|------|----------|--------|
| Webshell / 文件落地 | 上传 getshell、写文件 | 文件内容、进程、父进程、访问日志 |
| 命令执行 / 反弹 shell | RCE、漏洞利用 | 命令行、外连 IP、父进程、时间 |
| 异常登录 / 暴力破解 | 弱口令、撞库、VPN 登录 | 源 IP、账号、时间、失败/成功序列、MFA |
| 横向移动 | PTH/PTT/WMI/WinRM/PSExec | 登录类型、目标主机、账号、共享 |
| 扫描 / 目录爆破 | 资产探测 | 源 IP、UA、路径、频率、是否清单内 |
| C2 / 心跳 | 远控 | 周期外连、域名、TLS 指纹、进程 |
| DNS 隧道 / 数据外带 | 隐蔽通道 | 查询频率、域名长度、数据量 |
| 权限变更 / 账号创建 | 提权、持久化 | 账号、组、时间、操作者 |
| 计划任务 / 服务创建 | 持久化 | 名称、路径、命令行 |
| 数据库异常 | 注入、拖库 | SQL、返回行数、账号、时间 |

---

## 2. 研判流程

```
告警 → 收集上下文 → 资产归属 → 是否误报 → 定级 → 处置/升级 → 记录
```

### 2.1 收集上下文
- 原始告警、日志、流量、主机信息
- 资产归属、业务重要性、是否在护网清单
- 时间线：前后 30 分钟同类事件
- 账号：是否本人、是否异常地点/设备

### 2.2 是否误报
常见误报：扫描器自身、备份任务、运维脚本、监控探针、业务批量操作、CDN 回源。
判定：行为是否符合基线、是否有明确恶意特征、是否有后续动作。

### 2.3 定级
| 级别 | 判定 |
|------|------|
| 严重 | 已 getshell/命令执行/域控/核心数据外带 |
| 高 | 管理员权限、横向成功、可用凭证、持续 C2 |
| 中 | 未授权访问、有限数据、可疑但未确认 |
| 低 | 扫描、失败尝试、配置类 |

### 2.4 处置/升级
- 严重/高：立即隔离、取证、上报指挥部
- 中：加监控、限制访问、进一步确认
- 低：记录、观察、批量处理

---

## 3. 取证要点

- 保留原始日志/流量/文件（不要先删）
- 主机：进程、网络连接、账号、计划任务、服务、启动项、最近文件
- 内存/磁盘镜像（按需）
- 时间线：首次出现、持续、最后活动
- 证据编号与哈希

---

## 4. 与红队对抗的注意点

- 红队可能低特征、慢速、走合法通道；不要只看告警名
- 关注“行为异常”而非“特征匹配”：新进程、异常外连、权限提升、批量访问
- 蜜罐告警优先级高，但先确认真实性
- 不要打草惊蛇：确认前避免大规模封禁/通告

---

## 5. 交付

- 告警研判记录（每条：告警、上下文、结论、处置）
- 事件报告（升级为事件时）
- IOC 清单
- 复盘与规则优化建议

---

## 6. 一句话

**告警不是结论；看上下文、看行为、看后续；确认前不乱动，确认后快处置。**
